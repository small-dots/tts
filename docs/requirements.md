# Breeze TTS Studio 可视化工作台需求说明

**版本：** V1.0\
**项目类型：** 本地 Web 应用\
**开发目标：** 将 Breeze TTS 2 的语音生成能力封装为可视化操作界面\
**产品定位：** AI 语音设计、克隆与生成工具

---

## 一、项目背景

Breeze TTS 2 是支持中英文的文本转语音模型，能够通过参考音频或自然语言描述生成语音，并支持情绪、语气、语速及表达方式控制。

目前项目已经在本地启动，但主要通过命令行或 API 调用，操作不够直观。

本项目希望开发一个独立的 Web 管理界面，将模型的主要推理能力进行可视化封装，实现语音设计、声音克隆、声音指导、实时播放、音频下载及生成历史管理等功能。

### 1.1 建设原则

1. 不修改 Breeze TTS 2 模型的核心推理代码。
2. 优先复用现有 API 和推理能力。
3. 前后端分离，方便后续升级和部署。
4. 界面专业、简洁，适合长期使用，而非一次性 Demo。
5. 优先实现核心语音生成功能，避免过度设计。

## 二、功能范围与优先级

| 功能模块 | 主要功能 | 优先级 |
|---|---|---|
| 声音设计 | 通过自然语言描述生成语音 | P0 |
| 声音克隆 | 根据参考音频克隆声音 | P0 |
| 声音指导 | 对克隆声音进行情绪及表达控制 | P0 |
| 文本编辑 | 输入文本、语言选择、插入语音事件 | P0 |
| 音频播放 | 流式播放、暂停、重播、下载 | P0 |
| 任务状态 | 生成中、完成、失败及异常提示 | P0 |
| 生成记录 | 本地生成历史与音频管理 | P1 |
| 声音预设 | 保存常用的声音描述和参考音频配置 | P1 |
| 参数面板 | CFG、Seed 等高级参数 | P1 |
| 波形展示 | 展示生成音频波形和时长 | P1 |
| 批量生成 | 多段文本顺序生成 | P2 |

## 三、页面结构设计

采用单页面工作台设计，整体划分为三个区域：

### 3.1 左侧：功能导航

包括：

- 声音设计（Voice Design）
- 声音克隆（Voice Clone）
- 声音指导（Voice Direction）
- 生成历史（History）
- 声音预设（Presets）
- 设置（Settings）

三个核心功能使用统一的生成工作区，切换模式时动态更新相应参数。

### 3.2 中间：语音生成工作区

作为页面核心区域，包含：

1. 语音文本编辑器。
2. 参考音频上传区域（按模式显示）。
3. 声音描述或指导输入框。
4. 生成参数设置。
5. 开始生成、停止生成、重置按钮。
6. 当前生成状态。

### 3.3 右侧：生成结果

包含：

1. 最新生成的音频播放器。
2. 音频波形及播放进度。
3. 生成文本预览。
4. 语音生成参数摘要。
5. 下载音频按钮。
6. 最近生成记录。

桌面端采用三栏布局，小屏幕下可将右侧结果区改为底部面板。

## 四、核心功能详细需求

### 4.1 声音设计（Voice Design）

**功能目标：** 用户不需要提供参考音频，通过文字描述设计声音。

#### 输入内容

- 待合成文本（必填）。
- 声音描述 Instruction（必填）。
- 语言：中文 / 英文，作为界面辅助选择。
- CFG Scale，默认 4。
- Seed，作为可选高级参数。

声音描述支持直接输入，也支持使用预设模板。

#### 声音描述示例

中文：

> 一位温柔自信的年轻女性，声音清晰，语气亲切，表达轻快而富有感染力。

英文：

> A warm, thoughtful young woman with a clear voice and a calm, reflective delivery.

#### 交互要求

- 提供不少于 6 个可编辑的声音描述示例。
- 点击示例可快速填充描述。
- 支持修改描述并重新生成。
- 生成结果可以试听、下载、保存到历史记录。
- 不要求上传参考音频。
- Instruction 与目标文本保持相同语言，界面给予提示。

#### 验收要求

输入中文或英文文本及声音描述，能够正常生成对应音频，并完成播放和下载。

### 4.2 声音克隆（Voice Clone）

**功能目标：** 根据用户提供的参考音频，生成相似声音的新内容。

#### 输入内容

- 参考音频文件（必填）。
- 参考音频的准确文字稿 Ref Text（必填）。
- 目标生成文本 Text（必填）。
- Seed（可选）。

#### 交互要求

- 支持上传 WAV 文件。
- 支持预览及播放参考音频。
- 展示文件名称、文件大小和音频时长。
- 支持删除或替换参考音频。
- 提示用户使用干净、背景噪声较少的参考音频。
- 明确提示参考文本必须与音频实际说话内容一致。
- 上传文件后，可多次修改目标文本进行生成。
- 提供“我确认拥有该声音的使用授权”确认选项。

#### 验收要求

上传有效参考音频、填写准确文字稿与目标文本后，能够成功生成并播放音频。

声音相似度属于模型效果指标，不以主观完全一致作为功能验收标准。

### 4.3 声音指导（Voice Direction）

**功能目标：** 使用参考音频保持声音特征，同时控制生成语音的表达方式。

#### 输入内容

- 参考音频 Ref Audio（必填）。
- 参考音频准确文字稿 Ref Text（必填）。
- 目标文本 Text（必填）。
- 声音指导 Instruction（必填）。
- CFG Scale，默认 4。

#### 交互要求

提供常见指导描述供用户选择和修改，例如：

| 预设 | 指导示例 |
|---|---|
| 温柔 | 用温柔、亲切的语气说话 |
| 严肃 | 以克制、严肃的语气表达 |
| 兴奋 | 用兴奋且富有活力的方式表达 |
| 悲伤 | 以低沉、略带悲伤的语气说话 |
| 缓慢 | 放慢表达节奏，清晰地说出每个词 |
| 自然 | 使用轻松自然的日常交流语气 |

这些选项实质上是向模型传递自然语言 Instruction，不代表模型存在独立的情绪参数。

#### 验收要求

能够在参考音频基础上附加指导描述，正常完成推理。用户可通过多次生成对比不同指导描述产生的效果。

### 4.4 语音事件标签（Vocal Events）

Breeze TTS 2 支持在输入文本中添加语音事件标签。

#### 支持的标签示例

| 中文标签 | 英文标签 | 含义 |
|---|---|---|
| `[笑]` | `(laugh)` | 笑 |
| `[咳嗽]` | `(cough)` | 咳嗽 |
| `[清嗓子]` | `(clears throat)` | 清嗓子 |
| `[叹气]` | `(sigh)` | 叹气 |

#### 交互要求

- 在文本编辑器上方增加“插入事件”快捷按钮。
- 用户点击标签后，将标签插入光标所在位置。
- 中英文标签根据语言选择展示。
- 不自动删除用户手动输入的事件标记。
- 语音事件由模型生成，不另外叠加音效文件。

### 4.5 音频生成及播放

#### 生成过程

点击“生成语音”后：

1. 校验必要输入参数。
2. 展示生成状态。
3. 调用本地 Breeze TTS 2 服务。
4. 接收服务返回的 PCM 音频流。
5. 支持在接收到足够音频数据后开始播放。
6. 完成后保留完整音频用于重播及下载。

#### 播放器功能

- 播放 / 暂停。
- 重新播放。
- 播放进度及总时长。
- 音量调节。
- WAV 文件下载。
- 可选音频波形显示。

#### 技术要求

现有 API 输出：

- PCM
- 单声道
- 24,000 Hz 采样率
- 16-bit signed little-endian

前端应使用专门的 PCM 流播放器，可通过 Web Audio API 处理和缓冲音频，不得直接将原始 PCM 响应当成 WAV 文件使用。

下载时应将完整 PCM 数据封装为正确的 WAV 文件。

允许用户停止接收和播放当前请求；不将前端请求中断等同于模型计算一定已经停止。

### 4.6 生成历史记录

记录内容：

- 生成时间。
- 生成模式。
- 生成文本。
- 声音描述或指导参数。
- 参考音频关联信息。
- 生成音频文件。
- 任务状态。

支持：

- 按时间倒序排列。
- 播放历史音频。
- 下载历史音频。
- 删除历史记录。
- 使用历史参数再次生成。

第一版可使用本地文件系统保存音频与 JSON 元数据，不引入数据库。

参考音频默认不在历史记录中自动长期保存；需要持久保存时由用户明确选择。

### 4.7 系统设置

包含：

- 后端 API 地址。
- 推理服务连接状态。
- 模型运行状态（可查询时）。
- 默认 CFG Scale。
- 默认 Seed 策略。
- 音频输出目录。
- 生成记录保留策略。

模型运行状态、GPU 占用和显存监测不是当前 README 已提供的标准 API 能力。如需展示，应增加后端检测接口，不在第一版中假定已有这些数据。

## 五、接口设计

### 5.1 现有模型接口

根据 README：

`POST /v1/audio/speech`

使用 `multipart/form-data` 提交参数。

| 字段 | 用途 | 适用模式 |
|---|---|---|
| `text` | 待生成语音文本 | 全部 |
| `ref_audio` | 参考音频 | 克隆、指导 |
| `ref_text` | 参考音频文字稿 | 克隆、指导 |
| `instruction` | 声音描述或指导 | 设计、指导 |
| `cfg_scale` | 指令遵循强度参数 | 设计、指导 |
| `seed` | 随机种子 | 可选 |

以上字段来自 README 示例。具体字段校验规则、范围及可选性需以本地 API 实现为准。

### 5.2 Web 中间服务

建议增加轻量 Node.js 服务层，负责：

- 接收前端上传文件。
- 转发请求至 Breeze TTS 推理 API。
- 转发流式音频数据。
- 处理生成任务状态。
- 保存生成历史。
- 封装 WAV 文件下载。
- 提供简单健康检查。

建议接口：

| 接口 | 说明 |
|---|---|
| `GET /api/health` | 检查中间服务及推理 API 可用性 |
| `POST /api/speech` | 语音生成，透传 PCM 流 |
| `GET /api/history` | 获取生成历史 |
| `GET /api/history/:id` | 获取历史详情 |
| `DELETE /api/history/:id` | 删除历史记录 |
| `GET /api/audio/:id` | 获取历史音频 |
| `GET /api/audio/:id/download` | 下载 WAV 文件 |

这些是拟新增的 Web 服务接口，不是 Breeze TTS 2 已有接口。

## 六、技术架构

### 6.1 前端

- Vue 3
- Vite
- JavaScript
- Pinia（按需）
- Ant Design Vue
- SCSS
- Web Audio API

### 6.2 后端

- Node.js
- Express
- 原生 HTTP 流式转发
- 本地文件存储
- JSON 元数据管理

### 6.3 推理服务

复用已启动的 Breeze TTS 2 Python 推理服务。

默认请求地址：

`http://127.0.0.1:7860/v1/audio/speech`

实际端口应支持配置。

### 6.4 架构关系

```text
Vue 3 Web 工作台
      |
      | HTTP / Streaming
      v
Node.js API 中间层
      |
      | multipart/form-data
      v
Breeze TTS 2 推理服务
      |
      | PCM Audio Stream
      v
Node.js 流转发
      |
      v
Web Audio 播放器
      |
      +-- WAV 下载
      |
      +-- 历史记录
```

### 6.5 并发控制

README 说明当前推理 API 采用单并发模式。

第一版按单任务队列设计：

- 同一时间只允许执行一个推理任务。
- 新任务进入等待队列，或通过配置选择拒绝新任务。
- 页面展示等待、执行、完成、失败状态。
- 不允许多个浏览器同时绕过队列触发推理。
- 服务异常时提供重试或重新连接入口。

## 七、交互与视觉要求

### 7.1 设计风格

整体采用现代 AI 创作工具风格，避免传统后台管理系统的表格堆叠。

设计要求：

- 默认深色主题，可切换浅色。
- 页面整体简洁，信息层次清晰。
- 以文本输入、语音参数和音频结果为视觉中心。
- 使用卡片、分段控件和折叠面板组织功能。
- 支持加载状态、错误提示、空状态。
- 优先适配 1440px 及以上桌面屏幕，同时兼容常规笔记本屏幕。

### 7.2 关键交互

- 功能模式切换不应丢失当前已输入的数据。
- 不同模式展示不同的参数，不相关参数自动隐藏。
- 声音描述支持一键填充与手动编辑。
- 生成按钮应有明确的执行状态。
- 结果播放器应始终可见。
- 下载文件名支持按模式和时间自动生成。
- 网络异常、模型不可用、音频格式错误必须提供明确提示。

## 八、非功能性需求

### 8.1 性能

- 页面交互保持流畅。
- 推理期间页面不能阻塞。
- 音频流分块接收，避免每次收到新数据都重新复制整个音频缓冲。
- WAV 导出使用正确音频头和采样参数。
- 长时间生成任务需要清理临时文件和释放音频资源。

不承诺固定推理耗时或首音频延迟，以实际硬件及模型运行情况为准。

### 8.2 安全

- 默认仅供本机访问。
- 文件上传限制大小和类型。
- 上传内容仅用于当前授权的语音生成任务。
- 不提供未经授权的公开声音克隆服务。
- 不默认公开保存用户参考音频。
- 如后续对外部署，应增加身份验证、访问限制、文件清理策略及必要的声音使用授权措施。

### 8.3 可维护性

- 模型推理与前端界面解耦。
- API 地址通过环境变量配置。
- 统一错误处理。
- 统一音频任务状态管理。
- 组件化开发。
- 提供 README、启动脚本与部署说明。

## 九、开发阶段规划

### 第一阶段：MVP

完成：

1. Vue 3 工作台界面。
2. 三种核心生成模式。
3. 文本编辑及事件标签插入。
4. 参考音频上传与预览。
5. Node.js 中间服务。
6. PCM 流式音频播放。
7. WAV 文件下载。
8. 基础错误提示及单任务控制。

**交付标准：** 用户完全不需要使用命令行，即可在浏览器中完成三种语音生成任务。

### 第二阶段：使用体验提升

完成：

- 声音描述预设。
- 生成历史记录。
- 音频波形。
- 高级参数面板。
- 深浅主题切换。
- 历史结果复用。

### 第三阶段：高级能力

根据实际需求考虑：

- 多段文本顺序生成。
- 多种声音参数对比。
- 批量音频下载。
- 本地语音资产管理。
- 更细致的性能监控与日志。

以上属于后续应用层扩展，不代表模型本身已经提供对应接口。

## 十、明确不在 V1.0 范围内的内容

第一版暂不开发：

- 模型训练及微调。
- 多用户账号和权限系统。
- 商业化计费。
- 公开声音分享平台。
- 语音识别 ASR。
- 视频配音及字幕对齐。
- 多说话人自动分配。
- 分布式推理。
- 数据库及云端对象存储。

## 十一、最终验收标准

1. 三种语音生成模式均可通过 UI 正常使用。
2. 参考音频、目标文本及声音指导参数能够正确传递到模型。
3. 中文和英文语音均可正常生成。
4. 支持插入 README 明确列出的语音事件标签。
5. 能够正确播放模型返回的 PCM 音频流。
6. 能够将生成音频下载为可正常播放的 WAV 文件。
7. 错误输入和后端故障有明确反馈。
8. 不修改原始模型核心推理逻辑。
9. 前后端可独立启动，配置及使用方式有明确说明。
10. 满足单并发推理环境下的基本任务管理要求。

## 十二、部署及授权说明

README 中的官方推荐推理环境为 Linux、Python 3.10 及以上、NVIDIA CUDA GPU，并说明 eager 推理约需要 7.7 GiB 显存，推荐至少 12 GB GPU。

本项目的 Web 界面不依赖特定 GPU，但模型推理服务的实际性能和兼容性应以本地环境测试为准。

另外，README 明确区分了源代码许可与模型权重许可。开源权重、自托管推理输出受 BreezeBlue Research and Non-Commercial License 约束。即使开发完成 Web 工作台，也不意味着可以直接将自托管模型用于商业服务。

**V1.0 定位为本地研究、测试和非商业用途的可视化工具。** 商业部署需要另行核实和获得适当授权。
